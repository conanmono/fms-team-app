# Feature map — คู่มือและเกณฑ์ตรวจของ `/verify`

ฟีเจอร์มองจากมุมผู้ใช้ ใช้เป็นทั้ง **ขั้นตอนเดิน flow** และ **เกณฑ์ให้คะแนน** ตอน verify
ที่มาของกติกา: `docs/requirements/user-stories-and-test-cases.md` (R1–R10, US-xx)

> repo นี้ยังสร้างหน้าไม่ครบ (เป็นเป้าหมายของ workshop) ฟีเจอร์ที่ยังไม่มีหน้าให้รายงานว่า "ยังไม่มี — ไม่ได้ตรวจ" ไม่ใช่ "ล้ม"
> สร้างฟีเจอร์ใหม่เสร็จเมื่อไร ให้ปรับแถวนั้นให้ตรงกับ UI จริง (ข้อความปุ่ม, path) ใน PR เดียวกัน
> ตอนนี้มีแค่ F1 (`src/app/page.tsx`) ส่วน "ไฟล์ที่เกี่ยว" ของ F2 ขึ้นไปเป็น **ตำแหน่งที่แนะนำ** (route group `(front)`, `(auth)`, `(admin)`) ถ้าสร้างไว้ที่อื่นให้แก้แถวให้ตรง

## ฟีเจอร์

### F1 หน้าแรก และ layout รวม
- **smoke:** `/`
- **ไฟล์ที่เกี่ยว:** `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`
- **ขั้นตอน:** เปิด `/` แล้วดูหัวข้อและรูปโลโก้
- **ผลที่ต้องเห็น (ตอนนี้):** หน้าโหลดได้, มี `h1` ตามที่ `__tests__/page.test.tsx` คาด, รูปโหลดครบ, ไม่มี error หรือ hydration warning ใน console
- **ผลที่ต้องเห็น (เมื่อสร้างหน้าแรกจริงแล้ว):** หมวดหมู่ 5 หมวด, คอร์สยอดนิยม, ราคาเป็น `฿1,290.00` (US-14), ไม่มี `kubernetes-advanced` ให้แก้แถวนี้ใน PR ที่สร้างหน้าแรก
- **กรณีที่ต้องล้ม:** —

### F2 สมัครสมาชิก / เข้าสู่ระบบ (US-01)
- **smoke:** `/login`, `/register`, และ `--login user@example.com:password123`
- **ไฟล์ที่เกี่ยว:** `src/app/(auth)/`, `src/lib/auth.ts`, `src/lib/auth-client.ts`, `src/app/api/auth/`
- **ขั้นตอน:** สมัครด้วยอีเมลใหม่ `verify-<เวลา>@example.com` → ออกจากระบบ → login ด้วย `user@example.com`
- **ผลที่ต้องเห็น:** หลัง login เห็นชื่อผู้ใช้ใน header, refresh แล้วยังอยู่ในระบบ
- **กรณีที่ต้องล้ม:** รหัสผ่านผิด → ข้อความภาษาไทยที่เข้าใจได้ ไม่บอกว่าอีเมลมีอยู่หรือไม่; สมัครซ้ำด้วยอีเมลเดิม → ถูกปฏิเสธ

### F3 ค้นหาและกรองคอร์ส (US-02)
- **smoke:** `/courses`, `/courses?q=react`
- **ไฟล์ที่เกี่ยว:** `src/app/(front)/courses/`, `src/lib/course/`
- **ขั้นตอน:** พิมพ์ค้นหา "react" → กรองหมวด Frontend → กรองระดับ → เปลี่ยนการเรียง (ราคา/ใหม่ล่าสุด)
- **ผลที่ต้องเห็น:** ผลตรงเงื่อนไขทุกข้อพร้อมกัน, ค่าฟิลเตอร์อยู่ใน URL (refresh แล้วยังอยู่), ไม่มีคอร์สฉบับร่าง
- **กรณีที่ต้องล้ม:** ค้นคำที่ไม่มี → แสดง empty state ไม่ใช่หน้าขาว

### F4 รายละเอียดคอร์ส + ตะกร้า (US-03)
- **smoke:** `/courses/react-fundamentals`, `/courses/kubernetes-advanced=404`, `/cart`
- **ไฟล์ที่เกี่ยว:** `src/app/(front)/courses/[slug]/`, `src/app/(front)/cart/`, `src/stores/`
- **ขั้นตอน:** เปิดคอร์ส → ดูบทแรกฟรี → เพิ่มลงตะกร้า → เพิ่มคอร์สที่ 2 → เปิด `/cart` → ลบ 1 รายการ → refresh
- **ผลที่ต้องเห็น:** จำนวนในไอคอนตะกร้าอัปเดตทันที, ยอดรวมถูกต้องเป็นสตางค์, refresh แล้วตะกร้ายังอยู่ (localStorage)
- **กรณีที่ต้องล้ม:** เพิ่มคอร์สเดิมซ้ำ → ไม่เพิ่มซ้ำ; คอร์สที่ซื้อแล้ว (React ของ `user@example.com`) → เพิ่มไม่ได้

### F5 คูปอง + กระจายส่วนลด (US-04, US-05)
- **smoke:** —
- **ไฟล์ที่เกี่ยว:** `src/lib/coupon/`, `src/lib/checkout/allocate-discount.ts`, หน้า cart/checkout
- **ขั้นตอน:** ตะกร้ามี React (฿1,290) → ใส่ `WELCOME20`
- **ผลที่ต้องเห็น:** ส่วนลด ฿258.00 ยอดสุทธิ ฿1,032.00; ตะกร้า React + Next.js (฿3,780) + `WELCOME20` → ส่วนลดติดเพดาน ฿500.00; `SAVE200` → ลด ฿200.00 ใช้ได้ 1 ใบต่อคำสั่งซื้อ
- **กรณีที่ต้องล้ม:** `OLDCODE` → ข้อความว่าคูปองใช้ไม่ได้ ยอดไม่เปลี่ยน; โค้ดมั่ว → ปฏิเสธ

### F6 ชำระเงิน + ลงทะเบียน (US-06)
- **smoke:** `--login user@example.com:password123 /checkout`
- **ไฟล์ที่เกี่ยว:** `src/app/(front)/checkout/`, `src/lib/checkout/`, `src/lib/payment/`, `src/lib/enrollment/`
- **ขั้นตอน:** ยังไม่ login กด checkout → ถูกพาไป login → กลับมา checkout → บัตร `4242424242424242` → ยืนยัน
- **ผลที่ต้องเห็น:** หน้าสำเร็จพร้อมเลขคำสั่งซื้อ, ตะกร้าว่าง, `/my-courses` มีคอร์สใหม่, DB: `orders.status = 'PAID'` และ `enrollments` เพิ่มครบทุกคอร์ส
- **กรณีที่ต้องล้ม:** `4000000000000002` → แจ้งบัตรถูกปฏิเสธ, Order เป็น `FAILED`, ไม่มี Enrollment ใหม่, ตะกร้ายังอยู่; `4000000000000119` → แจ้งระบบชำระเงินขัดข้อง แอปไม่พัง

### F7 ประวัติคำสั่งซื้อ + คืนเงินรายคอร์ส (US-09)
- **smoke:** `--login user@example.com:password123 /orders`
- **ไฟล์ที่เกี่ยว:** `src/app/(front)/orders/`, `src/lib/refund/`
- **ขั้นตอน:** login `user@example.com` → `/orders` → เปิดคำสั่งซื้อ React → ขอคืนเงิน
- **ผลที่ต้องเห็น:** item เป็น `REFUNDED`, Enrollment เป็น `REVOKED`, คอร์สหายจาก `/my-courses`, ยอดคืน = `paidSatang` ของ item นั้น
- **กรณีที่ต้องล้ม:** คำสั่งซื้อเกิน 7 วัน หรือเรียนเกิน 20% (ใช้ `student01…20`) → ปุ่มคืนเงินไม่มีหรือถูกปฏิเสธพร้อมเหตุผล
- **หมายเหตุ:** flow นี้เปลี่ยน dev.db ถ้าจะทดสอบซ้ำให้ `npm run db:seed`

### F8 เรียน + ความคืบหน้า + ใบประกาศ (US-07, US-08)
- **smoke:** `--login user@example.com:password123 /my-courses`
- **ไฟล์ที่เกี่ยว:** `src/app/(front)/my-courses/`, `src/app/(front)/learn/`, `src/app/(front)/certificates/`, `src/lib/learning/`
- **ขั้นตอน:** `/my-courses` → เข้าเรียน React → กด "เรียนจบบทนี้" ทีละบทจนครบ
- **ผลที่ต้องเห็น:** progress = `floor(จบ/ทั้งหมด×100)` (6 บท: 1 บท = 16%), ครบ 100% ได้ใบประกาศรหัส `CT-YYYY-XXXXXX`, `/certificates/<code>` เปิดได้ตอน logout
- **กรณีที่ต้องล้ม:** ผู้ใช้ที่ไม่ได้ลงทะเบียนเปิด `/learn/react-fundamentals/<lessonId>` บทที่ 2 ขึ้นไป → ถูกปฏิเสธ; รหัสใบประกาศมั่ว → 404

### F9 รีวิว (US-10)
- **smoke:** —
- **ไฟล์ที่เกี่ยว:** `src/lib/review/`, หน้ารายละเอียดคอร์ส
- **ขั้นตอน:** login ผู้ลงทะเบียน → หน้าคอร์ส → ให้ 5 ดาว ข้อความ ≥10 ตัวอักษร
- **ผลที่ต้องเห็น:** รีวิวแสดงทันที, คะแนนเฉลี่ยอัปเดต
- **กรณีที่ต้องล้ม:** ข้อความ <10 ตัวอักษร → validation error; รีวิวซ้ำ → ไม่ได้; ผู้ไม่ได้ลงทะเบียน → ไม่เห็นฟอร์ม

### F10 คอร์สฟรีจาก API ภายนอก (US-11)
- **smoke:** `/free-courses`
- **ไฟล์ที่เกี่ยว:** `src/app/(front)/free-courses/`, `src/lib/free-course/`
- **ขั้นตอน:** เปิด `/free-courses`
- **ผลที่ต้องเห็น:** รายการคอร์สพร้อมรูปจาก `api.codingthailand.com`
- **กรณีที่ต้องล้ม:** API ล่ม (ให้ผู้ใช้รัน dev server ด้วย `COURSE_API_URL=http://localhost:9` — ห้ามแก้ `.env` เอง) → หน้าแสดงข้อความแทน ไม่พัง และตอบภายใน ~5 วินาที

### F11 หลังบ้าน (US-12, US-13, US-15)
- **smoke:** `--login admin@example.com:password123 /admin`, และ `--login user@example.com:password123 /admin=307` (หรือ 403/404 ตามที่ออกแบบ)
- **ไฟล์ที่เกี่ยว:** `src/app/(admin)/`, `src/lib/admin/`
- **ขั้นตอน:** login admin → `/admin` → สลับกราฟ 7/30/90 วัน → สร้างคอร์สฉบับร่าง → เพิ่มบทเรียน → เผยแพร่
- **ผลที่ต้องเห็น:** กราฟมีข้อมูลทั้ง 3 ช่วง (seed มีคำสั่งซื้อย้อนหลัง 90 วัน), รายได้นับเฉพาะ item `PAID` แบ่งวันตามเวลาไทย, คอร์สที่เผยแพร่โผล่ใน `/courses`
- **กรณีที่ต้องล้ม:** ผู้ใช้ทั่วไป/ไม่ login เปิด `/admin` หรือเรียก Server Action ของ admin → ถูกปฏิเสธ; ลบคอร์สที่มีคนซื้อแล้ว → ไม่ได้ (onDelete: Restrict)
